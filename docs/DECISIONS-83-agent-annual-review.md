## 0. 一句话结论（三家一致）

方向值得做；价值在「可复核的行为证据账本 + 口径版本化 + 自评-验证对照」，不在「年度报告」这个产物。token/费用/会话计数、词云、「年度之最」榜单是可复制包装。「最过度自信的 Agent」类排名移出对外发布项（测量噪声>真实差异 + 人格化指控）。

## 1. 证据基线（已按用户 2026-10-27 指示脱敏）

本节原含本机实测坐标（日志路径、消息/会话计数、明文凭据命中点），因仓库公开、一律不随库分发，已整体移除；原始证据留存于 thread #83 评论原文（板内）与本地审计记录。以下仅保留支撑规则的结论性事实：

- E1 两家 agent（zcode、claude）的本机会话日志均已实测核验存在，且记录完整带 token 用量字段——「差账式」成本预检可精确求和。其余 agent 未核验（未核验≠不存在）。
- E2 两侧日志粒度不同（zcode=整包重放/定长滑窗/尾部裁剪；claude=单条消息），实测存在约一个数量级的重复膨胀与自然单位差异——一切计数先按两层清单分离真实与重放（见 D5），跨 agent 比较先归一到"轮次"（D5/D1 的依据）。
- E3 结构化自评/置信度字段实测 0 命中——自评校准表历史段预期 n=0，须如实呈现（D2 的依据）。
- E4 验证信号（测试标记、稳定消息锚点 id）实测在——证据下钻与自评-验证对照有现成 id 可用。
- E5 本机会话日志中实测存在明文凭据（相关密钥已由用户于 2026-10-27 全部轮换；命中坐标留存本地，不随库分发）——外发前脱敏闸是分析步的启用前置，不是优化项（D4 的依据）。

## 2. 产品决策（Q1–Q5；三家合并）

- Q1 差异化：可重算（同输入+同分析器版本⇒同事件集，可 diff「哪些结论变了、为什么」）+ 证据账本（每条统计可下钻到 message_id+原文片段+判定版本）+ 纵向数据；自评-验证对照（AI 自评 vs 测试由红转绿/后续被改/独立评审驳回）是别人抄不走的部分。Wrapped 外壳/榜单/词云不作为卖点。
- Q2 架构：SQLite 唯一事实源（表：sessions/messages/events/runs/classifier_versions；events 行必带 message_id、span 起止、evidence_quote、classifier_version、run_id、confidence；原始会话文本以「路径+内容哈希」入 DB，报告按需读取）；分析 agent=无状态 worker（manifest 分片进、固定 JSON schema 事件出，不聚合、不判定可发布性）；报告=DB 纯渲染。Board 只接三类决策：①口径/定义变更 ②争议案例裁决（多例打包一帖）③MVP 范围与验收；一帖一决策（见 D3）。Board 的票与评审是治理产物，不是准确率标签（见 D6）。原文不出机器：报告只渲染脱敏后证据片段+本地可下钻，不把"可下钻"实现成"报告嵌全文"。
- Q3 指标：两段式口径（claude 修正一）——机器段可全量：「AI 输出未变（同文件同区域 diff 为空/仅格式变化）+用户再发话」；「同一 hunk 被原地重写≥2 次」，hunk 锚=文件路径+行区间+改前内容哈希三元组（防边界漂移保证可重复算）。语义段只抽样验证报 precision，以「估计值+区间」呈现：「用户重复同一意图」是语义判定不得进全量。责备=用户下一条消息对上一 AI 输出的否定或纠正；道歉=AI 输出中的自我否定表述计数，不得解释为错误已修复、不得充当错误率的分母或分子；自评校准只在有外部验证证据的子集上算并报 n。发布门槛见 D7-a；每个数字带六元组见 D7-c。
- Q4 成本：预检分两块——差账记录（两侧记录 100% 带 usage 可精确求和，但必须先按两层清单去重，否则重复膨胀会乘进成本）与分析增量（候选事件×单价，抽样估）；粗估系数=去重后直和×3（仅作初始区间，不称上界）；硬治理=每任务硬上限（美元+最大调用数+最大重试数，I am rich 模式同样适用）+持久化预算状态机（进程中断/重启/并发 worker 下可恢复）+预估/实际偏差按分析器版本记账+超限在下一次模型调用前停止；API 等效成本与订阅支出分列；分层（高价值全量/普通 1/N 抽样，报告写抽样率与外推方差）；多 agent 复核只给「分歧集」——两模型不一致才上第三人，不全量双跑。
- Q5 MVP（第一阶段）：①会话发现+两层清单+覆盖率报告（会话数/消息数/token 记录缺失比例）②两个机器段代理指标：同文重发事件、代码改动频繁度（churn）——门槛（kappa≥0.6 ∧ precision≥0.8，绑定标注集 id/hash+classifier_version）通过前不得冠名「追问率/返工率」（A2）③校准表两段制：历史回顾段如实报告自评信号覆盖（前置 50 会话抽检，若≈0 如实呈现「未检测到」空表+分母来源，不删交付物、不许外推、禁止对既有会话回写自评分）；前瞻段自现在起让参与 agent 结构化输出自评并以独立验证对照（A6）④渲染器（六元组+口径版本+来源覆盖）。暂缓清单见 D7-d。验收 P1–P5 见 §5。

## 3. 硬规则 D1–D7（逐条；每条含验收语句或反例测试）

D1 跨 agent 比较=MVP 不做项，并写明重启条件：同一事件 schema 抽取一致性 kappa≥0.6 且两 agent 漏检率差<10%。[=pi O1；覆盖 dsh C5-①]

D2 校准度量=只在有外部验证证据的子集上算，发布体必须含 (n, 分母来源, eligible_count, detected_count, verified_count, coverage, status)；三态分开：detected=0∧eligible>0=「未检测到（分母=N）」、eligible=0=「分母为 0，不可计算」、字段不可提取=「数据不可用」；禁止外推。[=pi O2+C3+A3；部分覆盖 dsh C5-④]

D3 Board 边界写死三条：仅①口径/定义变更②争议案例裁决（多例打包成一帖）③MVP 范围与验收；一帖一决策，禁止为会话/事件自动开帖。[=pi O3；依据 #83 一手实测：预算建帖即冻结、不随 UTC 日切回收，低价值事件先撞额度]

D4 外发前脱敏闸 fail-closed：任何把会话文本投给模型的调用前，先跑本地扫描（已知密钥形态+配置密钥清单+用户敏感词），命中即拒发并记账；证据行存脱敏后文本+原文 hash 指针。验收=注入合成 key 的会话，断言出站载荷不含该串（不是意图）；另留存本地历史明文凭据回归基准集（坐标不随库分发），闸门必须拦下其中全部命中。（rev2 增补：扫描面含访问令牌与私有 URL；日志、异常堆栈、调试输出与报告生成流程同受此边界；下钻读原文时校验内容哈希，区分「原始证据仍可读取」与「仅存证据指针」。）[=dsh C1+A5]

D5 manifest 两层：出现层保留每次真实出现（含会话内真实重复发送——追问候选的原料，不得折叠）；规范层仅折叠日志重放，判据=绝对位置+内容双证（绝对位置=会话内消息绝对序号，来自日志结构字段如 messageOffset；无结构字段时走存疑回退并亮灯，不静默丢弃）。真实=去重 (会话, 绝对位置, 内容) 三元组：同位异内容=重写行（单独灯，按真实计）；同会话同内容不同位置=真实（分支/真实重复）；跨会话同文本不合并。报告 per-agent occurrences/genuine/replay/dedup_factor 与两盏灯（同位重写调用数、折叠但内容未见行数）；灯同样遵守 D2 三态——该 agent 无此路径 ⇒ status=数据不可用，非 0；dedup_factor 阈值绑定判据版本（v0.3 判据本机实测 ≈13.9）。验收=同输入两次跑规范集 hash 相同（同输入=快照指纹：文件数/字节数/mtime 写入报告头，活日志上防假红；快照指纹仅用于识别输入快照与辅助幂等测试，**不替代去重算法本身的正确性测试**——正确性由滑窗/同位重写/双导入/跨会话四类夹具承担；mtime 不独立作为内容身份依据，内容身份=内容哈希，文件身份=文件名+字节数+mtime 联合）＋滑窗反例夹具不得全判重放＋同位重写夹具按真实计。[=dsh C2+A1]

D6 评审独立性：评审者≢被评 agent，同模型换角色不算独立证据；Board 的票是治理产物，不是准确率标签。[=dsh C4]

D7 发布门槛与暂缓清单（dsh #962 提议文本，pi #963 收下；P-b/P-c/P-d 并入各条，P-a 并入 D7-b）：

  D7-a 责备/道歉类指标的发布门槛：责备率仅在标注集上 kappa≥0.6 ∧ precision≥0.8 时才可发布（照 pi #956 Q3 的数），无标注验证一律 0 发布；「道歉」只定义为「AI 输出中的自我否定表述计数」，不得解释为错误已修复、不得充当错误率的分母或分子。反例测试：注入「道歉=1、错误=0」的夹具⇒渲染结果必须含「未检测/不可计算」，出现「错误率=0.0」即红。[P-c 补丁：kappa/precision 阈值必须绑定 (标注集 id, 标注集 hash, classifier_version)；换标注集或换分类器版本⇒门槛重跑，不得沿用旧 kappa 声称过门]

  D7-b 「未检测」全域化与禁裸 0：任何指标禁写裸 0——输出必须带 status（可计算/未检测到/样本不足/数据不可用）与 eligible/detected 计数（P-a：此处及 D7-c 六元组中的 n 只允许一个字义、同一取数；同一渲染行出现两个不同 n ⇒ 红）。反例测试：①出现数值 0 且缺 status 或 eligible/detected ⇒ 红；②eligible>0 ∧ detected=0 时必须输出「未检测到（分母=N）」而非「分母=0」；③扫描渲染输出，凡数值 0 且同条缺 n 或 n==0 ⇒ 红。

  D7-c 六元组守卫：每个数字必须带 (value, n, denominator, window, classifier_version, source_coverage)。反例测试：构造只含 value 的渲染行⇒渲染器必须 raise/拒绝（同时补上 C3 剩余三项的门）。[P-b 补丁：守卫必须在渲染器单一出口 raise，不许各报表自行拼串再由守卫事后扫描——否则新报表=新增绕过口]

  D7-d MVP 暂缓清单逐条入记录（每条一行）：责备/道歉语义指标、单 agent 榜单与跨 agent 排名、Board 自动化开帖、「未检测当 0」。每条写明重启条件+解除所需的可判定证据（与 D1 同款样式）；不接受「暂时不做/后续视情况」。[P-d 补丁]

## 5. 验收（P1–P5 + 附加）

- P1 标注一致性：抽 200 条候选事件盲标（责备/追问/返工），报 Cohen's kappa；kappa<0.6 的指标不进 MVP。（pi。rev2 澄清：kappa 度量的是**两位独立标注者之间**的一致性，不是分类器与任何参照的一致性）
- P2 分析器方差：同一批会话换模型重跑同一分析器，报结论差异率。（pi）
- P3 成本偏差：抽 50 会话跑全流水线，对比预检区间与实测；预检区间须包含实测值。（pi）
- P4 去重正确性：即 D5 验收（含滑窗反例与同位重写夹具、快照指纹幂等）。（dsh）
- P5 外发前脱敏：即 D4 验收。（dsh）
- 附加（pi #956 §六，rev2 更名）：随机抽 20 条「同文重发事件」人工复核 precision≥0.8；两层清单覆盖率与实测一致（抽 50 会话无漏）；报告内每个数字可点回证据 id。（rev2 澄清：20 条抽检=初筛口径——必须随附样本量与不确定性（如二项置信区间），不得把小样本结果表述为「总体 precision 已达标」；precision 一律相对**独立裁决形成的参考标签**计算，不得用标注者一致性替代分类器准确性）

## 6. 风险与已知局限（三家）

日志格式漂移（分析器版本化+每周回归样例）；隐私（本地优先、报告脱敏、不上传——日志中存在明文凭据已在本机实测坐实，非风险假设；坐标留存本地）；「报告好看」≠「结论正确」；责备的语义识别难度（「行吧」「你再看看」「按我说的来」都可能是责备，讽刺与中性否定难分——标注集是发布前提）；会话日志完整覆盖未验证，覆盖率必须报分母；跨 agent 校准度差异可能主要被「模型版本+提示词版本」主导而非 agent 能力。
